## 4. 每位角色要产出什么

### 4.1 人设研究（联网，逐位做）

对每位角色查证并记录（**每条结论都要能指出来源链接**）：

| 字段 | 说明 |
|---|---|
| 官方名 / 英文名 / 别称 | 用于生成 id 与检索（**优先官方英文名**，便于和既有 id 风格一致） |
| 所属阵营 / 职业 / 定位 | 填 `faction`、`shipType` 字段（这两栏在主界面列表里显示为"阵营 · 职业"） |
| 身份与背景 | 一两句话，作为角色卡主体素材 |
| 性格与说话风格 | 语气、口癖、句尾习惯、自称、常用的比喻/意象 |
| 对玩家的称呼 | 既有角色用「指挥官」；新角色要用该作品里对玩家的称呼（如"管理员""师门称呼"等），并在角色卡里写明 |
| 招牌元素 | 3~5 个能自然写进台词的物件/动作/梗（避免生硬堆砌） |
| 不适合的内容 | 任何涉及现实政治、真实人物、露骨或攻击性的内容一律不写 |

**建议来源**：官方站点与官方 wiki、萌娘百科/百度百科词条、游戏内公开资料整理帖。
**必须避开**：非官方"剧透"文本、粉丝二创台词、语音转录文本（照抄风险）。

### 4.2 台词文件 `assets\builtin\lines\<id>.txt`（每位一份）

- **格式**（与现有素材完全一致，解析器在 `src\Store.cs` 的 `LinePack`）：
  ```
  # 注释行（# 或 // 开头会被忽略）
  @问候
  [10|22|gold|bold] 台词语句
  [3] 另一句
  @点击
  ...
  @主动
  ...
  @待机
  ...
  @系统
  [5] 现在是 {time}，汝还在忙么…      ← 可用占位符 {app} {main} {title} {idle} {time}
  ```
  `[]` 里依次是 **权重 | 字号 | 配色 | bold**，全部可省略；配色名可用 `gold / white / rouge / indigo / candy / cyan / ok` 或 `#RRGGBB`；
  也可在台词后用 `| 文件名.mp3` 指定内联语音（**本次新角色一律不写这一段**）。
- **数量下限**（自检会按这个门槛卡每一位内置角色，务必写够）：
  **问候 ≥5、点击 ≥8、主动 ≥4、待机 ≥3、系统 ≥3**（合计 ≥23 条/位）。
- **每位必须包含这三句**（自检硬性断言，用该角色的口吻改写，不能照抄原文）：
  - 「你好」意思的问候句
  - 「你终于回来了」意思的回归句
  - 「你怎么不理我」意思的待机句
- 写法要求：**口语短句**（≤30 字最佳，气泡只有一行到三行）；同一位角色的句子要有辨识度（自称、口癖、意象一致）；不要写成说明书。
- 语音片段：**不写**（见 §4.4）。

### 4.3 角色卡 `assets\builtin\characters\<id>\card.txt`（每位一份）

- 结构照抄既有素材（`assets\builtin\characters\shinano\card.txt` 等），保持**同样的分节标题**：
  `【角色设定】`、`【说话风格】`、`【开场白】`、`【补充要求】`（若既有文件用的是别的标题，就与之一致）。
- 内容：身份背景 2~3 句 + 语气与口癖 + 对玩家称呼 + 3 条以内输出约束（如"一次 1~3 句、60 字以内"）。
- **中文字符数 ≥150**（自检断言），建议 300~450 字。
- 作品名按 D3 决定是否出现。

### 4.4 语音策略（默认：不带语音）

- **不做**：抓取/转码游戏内语音、套用声优音色做模仿、把任何官方音频打进安装包。
- **默认产物**：`assets\builtin\voices\<id>\` 目录**不创建**（自检对"没有语音目录"是放行的，只在目录存在时校验 `manifest.txt`）。
- 若用户选 D1-B（本地 TTS）：音频放 `assets\builtin\voices\<id>\v01.mp3…`，并写 `manifest.txt`（每行 `文件名|台词文本` 或 `台词文本|文件名`）；
  **必须**在 `素材清单.md` 与 `使用说明.txt` 里注明"合成音，非官方配音"。
- 无论哪种：`profile.json` 的 `interact.fixedVoiceMode` 保持默认 `match`。

### 4.5 立绘处理 `assets\builtin\characters\<id>\portrait.png`

沿用既有内置素材的规范（自检会逐张校验）：

1. 裁掉透明边（四边透明像素包围盒，留 2px 余白）；
2. 等比缩放到**高度 ≤900**；
3. **32bpp ARGB**（保留 alpha），文件**≤1.2MB**；超了就做**保色量化**（RGB 每通道保留 7 bit 后重编码 —— 注意：**绝不能用亮度索引表转 8bit 调色板**，那会把立绘变灰度，是上一版修过的 bug）；
4. 自检的 4 项断言必须过：体积 ≤1.2MB、高度 ≤900、四角透明、**是彩色的**（最大通道反差 ≥40）。
> 省事做法：写一个临时小工具 `/r:AzurLaneDeskPet.exe` 直接调产品自己的 `ImageFx.TrimTransparent` / `ImageFx.ScaleToHeight`（既有工具链就是这么做的），处理完把临时工具删掉。

### 4.6 元数据 `assets\builtin\characters\<id>\info.json`

照抄既有结构：`id / name / ship / faction / type / artist / note`。
- `name` 用中文名（如 `米雪儿`）；
- `faction` / `type` 填该作品的阵营与职业（见 §4.1）；
- `note` 写"内置角色：台词与人设由联网资料改写，立绘来自用户提供的参考图片"这一类说明。

### 5.2 「开箱即用」补齐逻辑（必须改，否则老用户升上来看不到新角色）

- 现状：`src\Program.cs` 的 `SeedBuiltinCharacters()` —— `if (Config.Current.builtinSeed >= 1) return 0;`，即"每个数据目录只补一次"。
- 目标行为：
  - **新用户**：首次运行补齐**全部 13 位**；
  - **老用户升级**（原 `builtinSeed=1`）：自动补上这 **8 位新角色**，原有 5 位及用户自建角色**不受影响**；
  - **用户自己删掉的不会被复活**。
- 推荐实现（`AppSettings` 加一个字段，例如 `public string seededBuiltin = "";`）：记录"已经向这个数据目录提供过哪些内置模板 id"（逗号分隔）。
  - 首次运行或字段为空且 `builtinSeed == 1`（老配置）→ 视为"已提供过原有 5 位"，只补**不在该名单里**的模板；
  - 每次补齐后把当前全部内置 id 写回该字段；同时保持 `builtinSeed = 1` 兼容旧逻辑。
  - **不要**用"把缺失的内置角色全补一遍"的粗暴做法（会把用户删掉的复活）。
- 文案：`StartupTip`（"已为你准备好内置角色：…"）与日志"已补齐内置角色 N 位"跟着实际数量走。

## 6. 检索与写作流程（建议按这个顺序）

1. 先抽检 8 张图：四角 alpha、是否有纯色底（有底就要先抠图）、主体是否完整；
2. 逐位联网查 §4.1 的 7 个字段，**边查边把来源链接记到一个临时清单**（最后并进 `素材清单.md`）；
3. 逐位写台词（先写"必含三句"，再补足数量下限，最后按角色气质调权重/配色）；
4. 逐位写角色卡（≥150 中文字符）；
5. 处理 8 张立绘（§4.5）并核对 4 项指标；
6. 改 §5.2/§5.3 的代码与断言；
7. 构建 → 自检 → 修到全绿 → 出新安装包 → 交付。

## 7. 构建顺序（工程根 = `E:\桌宠\通用版本-工程`）

```powershell
# 1) 构建 + 核心自检（会新增 8 位角色的断言）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build.ps1
# 2) 界面自检 + 出截图
dist\app\AzurLaneDeskPet.exe --selftest-ui --report=dist\自检报告-界面.txt --render-ui=dist\ui-shots
# 3) 重建安装包
powershell -NoProfile -ExecutionPolicy Bypass -File installer\build-setup.ps1
```

> ⚠ 构建/交付脚本里的 `.ps1` 一律 **UTF-8 with BOM**；用编辑工具改过脚本后必须确认 BOM 还在（没有 BOM 时 PowerShell 5.1 会按 ANSI 解码而报语法错）。
> ⚠ 用 `[System.IO.File]::ReadAllText/WriteAllText` 时**必须传绝对路径**（PowerShell 的位置与进程当前目录可能不一致，曾因此把改动写进别的工程目录）。
