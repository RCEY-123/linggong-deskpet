# 灵工桌宠（Azur Lane Desk Pet）

把桌宠放到 Windows 桌面上的桌面宠物软件（内置角色素材版权归原权利人，见 §八）。参照 **DSH 小鲸鱼记账挂件**（`<参考实现工程>`，未做任何修改）的核心能力重做：自定义角色立绘 / 台词 / 语音清单 / 角色卡 / 互动音效、点击随机台词气泡、按压 Q 弹动画、多角色独立。

- **产物目录**：`<工程根>`
- **安装包**：`dist\灵工桌宠-安装程序.exe`（单文件，可选安装目录，免管理员）
- **主程序**：`dist\app\AzurLaneDeskPet.exe`（.NET Framework 4.x，系统自带 csc 编译，无第三方依赖）
- **卸载器**：`dist\app\卸载-灵工桌宠.exe`（安装后位于安装目录根下）
- **版本 / 作者**：v1.1.0 / 睡不着のHATSUZUKI（灵工巧物 · 天祈智临）

## 四、实现要点（为什么这么做）

- **逐像素透明**：桌宠用 `UpdateLayeredWindow` 分层窗口，透明区域点击直接穿透到桌面，不挡鼠标；立绘先转成**预乘 alpha** 再缩放，避免半透明边缘发黑。
- **桌宠显示方式**：三种（始终最上层 / 焦点冻结 / 全屏隐藏）由 `DisplayWatch` 一个纯函数决策表算出来，`PetForm.ApplyDisplayState()` 只做「状态真的变了才动窗口」的幂等应用（置顶 → `SWP_NOACTIVATE`，冻结 → `HWND_BOTTOM`，后台 → `Hide()` 并保持置顶标志以便回来时直接在最上面）。冻结/后台时统一停表、停语音、收气泡，并把暂停时长从互动计时里扣掉。
- **Q 弹动画**：按下立即压扁（底部坐标不变）、松开走「下压 0.83 → 过冲 1.10 → 微颤回正」曲线，30fps 只重绘 33ms 一帧；静止时**完全停表**（空闲 CPU 接近 0）。
- **内存**：立绘只保留一份预乘位图 + 两块复用画布（不逐帧 new Bitmap）；列表缩略图走独立缓存；`ImageCache.Clear()` 统一释放。
- **不透明立绘**：自动改画成「圆角 + 金边 + 投影」卡片，整张可点；想走透明路线就用「一键抠图」（纯色背景洪水填充 + 1px 羽化，原图自动备份）。
- **大模型兼容**：只依赖 OpenAI 兼容的 `/chat/completions`，所以云端（DeepSeek/OpenAI/中转）与本地（Ollama/LM Studio/OneAPI/llama.cpp）同一套代码；错误按 HTTP 码翻译成人话（401 鉴权、404 地址、429 限流…）。
- **权限与隐私**：系统监听默认关闭且必须显式授权；只读程序名/窗口标题/空闲时间，30 分钟滚动丢弃，不落盘；数据目录与日志全部本地。
- **错误处理**：所有入口都有 try/catch；异常一律落盘 + 专用弹窗给路径，并明确要求「上传日志而不是截图」。

### v1.0.8（本次：修三处用户实测问题 —— 欧根亲王灰度立绘 / 设置莫名丢失 / 关机被阻止）

**A. 欧根亲王的立绘是黑白的（立绘制作环节的 bug）**

- **原因**：欧根亲王的立绘在高 900 时 32bpp PNG = 1,278,448 B，超过需求的「单张 ≤1.2MB」上限；上一版按预案改写成 8bit 调色板 PNG，但用的调色板是**亮度索引表**，整张立绘被压成了灰度图 —— 而当时的自检只看「文件在不在」，所以没能拦住。
- **修复**：改成**保色量化**（RGB 每通道保留 7 bit，仍是 32bpp ARGB、alpha 不变）后重新编码：1,278,448 B → **919,396 B（897.8 KB）**，1272×900，颜色 / 透明 / 构图与用户参考图一致。
- **回归**：自检给每张内置立绘加 4 项断言 —— 体积 ≤1.2MB、高度 ≤900、四角透明、**必须是彩色的**（最大通道饱和差 ≥40 且灰度像素占比 <60%）。欧根亲王实测最大饱和差 178、灰度像素 9.3%（其余四张 6.9%~13%，改前它是 100%）。

**B. 改完设置、关掉再打开，设置「全部消失」变回初始状态**

- **真因（这次排查到的）**：不是程序没保存，而是**我们的验收 / 测试脚本把用户的真实数据目录 `%APPDATA%\AzurLaneDeskPet` 删掉了**。`final-acceptance.ps1` / `test-installer.ps1` 要走「装 → 用 → 卸」全流程，而卸载器按需求 8「卸载要清干净」默认就删数据目录 —— 于是每跑一次验收，就把用户自己的角色、台词、设置一起清掉了。（日志证据：数据目录被清后再启动是「新建角色 4fe16d53（信浓）… 已补齐内置角色 7 位」，`builtinSeed` 重新变回 1、`volume` 回到默认 80。）
- **修复**：
  1. 数据目录可由环境变量 **`AZURLANEDESK_PET_DATA`** 覆盖（主程序与卸载器都认），主程序另加命令行 **`--datadir=<目录>`**（与自检用的 `LockDataDir` 同一套锁定机制）；
  2. 三套验收脚本全部把数据目录指向 `%TEMP%` 沙箱，并各自新增断言 **「用户真实数据目录文件数未变」**，以后跑验收不可能再碰真实数据；
  3. 配置加安全网：每次保存都同步一份 `config.json.bak`；`config.json` 损坏时自动从备份恢复；连备份都不可用时**绝不静默覆盖**（先把坏文件改名 `config.json.bad-*` 留档再写新的）。
- **说明**：已经被删掉的自定义内容找不回来（内置模板素材都在安装包里，重新导入即可）。

**C. 桌宠运行时关机，Windows 报「此应用正在阻止关机」**

- **原因**：主界面 `OnClosing` 里「桌宠还在跑 → `e.Cancel = true` 只收起界面」对**系统关机请求**也生效，关机请求被顶回去 → Windows 判定本程序在阻止关机（桌宠没跑时还会弹「确定退出？」确认框，同样卡住关机）。
- **修复**：
  1. 新增关闭决策表 `MainForm.DecideClose(原因, 是否在退出流程, 桌宠是否在跑)`：**关机 / 注销 / 任务管理器结束任务 / Application.Exit 一律立刻放行**，不弹任何框；只有「用户点 X 且桌宠在跑」才收起界面，「用户点 X 且没桌宠」才问一句；
  2. 订阅 `Microsoft.Win32.SystemEvents.SessionEnding`：系统要关机时先把设置保存好、把桌宠与托盘收掉、停掉显示监听，然后立刻退出进程，并全程 `Log.SuppressDialogs = true`（不可能卡在弹窗上）；
  3. 自检新增第 ㉒ 组共 15 项：决策表 7 项 + 真窗口 / 真桌宠 8 项（关机请求不被取消、桌宠被停掉、`ShuttingDown` 置位、弹窗被抑制、显示监听停止）。

**B. 判定与开销（不采集隐私）**

- 只用本机 Win32 接口判定「前台窗口是谁、是否盖满屏幕」：`GetForegroundWindow` +
  `GetWindowRect` + `GetMonitorInfo` + 中心点命中校验，**不截屏、不读窗口标题、不落盘、不外传**。
- 桌面 / 任务栏 / 开始菜单 / 搜索 / 输入法浮层、以及桌宠自己的窗口**都不算「别的程序」**
  （按窗口类名 + 进程名双重判定），不会误触发。
- **多显示器**按屏幕分别判断：另一块屏上的全屏程序不会把这块屏的桌宠收走。
- **零轮询兜底**：选「始终最上层」且关掉全屏自动隐藏时，监听定时器**根本不启动**；
  需要时也只在「前台窗口变了」或每秒一次才真正探测一次，其余 tick 只调一次
  `GetForegroundWindow`（几微秒）。
- 性能坑（本轮实测发现并修掉）：`Process.GetProcessById(pid).ProcessName` 每次都会
  `NtQuerySystemInformation` 枚举整机所有进程线程，放进 300ms 定时器后空闲 CPU 从 0 涨到
  **969 ms / 20 秒**；改用 `OpenProcess + QueryFullProcessImageName`（几十微秒）并按 pid 缓存后
  降到 **31 ms / 20 秒**（约 0.15% 单核），关掉监听则仍是 **0 ms**。

**C. 冻结/隐藏时的细节**

- 冻结（沉底）不会把桌宠藏起来：窗口仍在桌面上（`SetWindowPos HWND_BOTTOM`），**实测仍在桌面
  图标层之上**（自检断言 Z 序：桌宠 < 其他窗口，且桌宠 < 桌面外壳）。
- 冻结/进后台时：Q 弹动画停止并回到正立帧、主动对话与待机定时器暂停、当前语音停止、
  气泡与输入框收起、**问候语跳过**（开机自启正赶上全屏程序时不会只响声音）；
  恢复时把「被冻结的时长」从互动间隔里扣掉，不会一恢复就立刻说待机台词。
- 等大模型回复期间被冻结：回复回来**不再弹气泡**盖住别人正在用的程序（只写日志）。
- 用户碰过桌宠（点击 / 拖拽 / 发消息）后有 **4 秒宽限期**：这期间不会被冻结或隐藏，
  点一下就能把它叫回来。
- 进入冻结/后台会写一条 INFO 日志（用户问「桌宠怎么不见了」时可直接查原因），回到正常只写 DEBUG。

### v1.0.2（本次修复）

**现象**：互动设置里对话模式切换不灵——处于大模型模式时点「固定台词模式」没反应，而且两个按钮同时亮着。

**根因**（三个叠加）：

1. `AlButton.Primary` 是**公开字段**，赋值不会触发重绘。切换模式只改状态、鼠标不动，于是按钮一直显示旧样子——看起来「点了没反应」。
2. 未选中按钮的**鼠标悬停**样式以前也是金色描边+金色文字，和「已选中」几乎一样；鼠标停在另一个按钮上时两个都像被选中。
3. 切到大模型且还没配接口时会**同步**弹出模态对话框，按钮收不到 MouseUp，`_down` 停在按下态，于是按钮一直亮着。

**修复**：

- `Primary` / `Danger` 改成属性，setter 里 `Invalidate()` + `Update()` 立即重绘（台词页的段落按钮等同类地方一并受益）。
- 选中态单独画一个**金色对勾**；未选中按钮的悬停改成「蓝色浅高亮」，不再用金色（金色＝已选中，语义唯一）。
- 模式面板加一行状态文字「当前：固定台词模式 / 当前：大模型对话模式（⚠ 还没配置接口）」。
- 按钮按下时抓鼠标（`Capture`）+ `OnMouseCaptureChanged` 兜底，模态窗口弹出也不会留下假按下状态；「还没配接口」的提醒改成点击处理之后再弹（`BeginInvoke`）。
- 模式切换即时落盘并立刻通知正在显示的桌宠，不用等防抖。

## 七、已知限制

- 只支持 Windows（.NET Framework 4.x，系统自带，无需额外安装运行时）。
- 抠图面向**纯色/近纯色背景**；复杂背景（照片、场景图）无法自动抠净，此时会按卡片样式显示——这是有意为之，比硬抠出锯齿好。
- GIF 动图目前只取首帧作为立绘（静帧）。
- 大模型请求为非流式（一次性返回后整段显示在气泡里），气泡内不适合放长篇回答，角色卡里已内置「1~3 句、60 字以内」的输出约束。
- 大量语音（上百条）首次进入「角色语音」页时校验需要极短时间，属正常。

├─ 安装说明（先看这个）.txt        ← 一分钟上手 + 安全说明
├─ 使用说明.txt                   ← 完整用户手册（与安装包内那份逐字一致）
├─ README.md                      ← 本文件
├─ SHA256SUMS.txt                 ← 关键产物 SHA-256，可自行核对
├─ app\                           ← 免安装绿色版（与安装负载逐字节一致，可直接跑）
├─ src\ installer\ assets\         ← 源码与素材（按第三节可重新构建）
├─ 测试报告\                       ← 01 核心自检 / 02 界面自检 / 03 安装器验收 /

  `ui-shots-installed`（旧截图）、`<用户参考图>`（需求方原始参考图目录，属本机素材，不进交付）、
  任何 `%TEMP%` 测试痕迹、以及 `installer\` 里与 `测试报告\` 重复的那两份验收报告。

### 已知边界：更早期版本（v1.0.3 及以前）留下的、任何清单都没记录的残留

安装包从 v1.0.4 起用 `files.json` 记录「本次写了什么」，v1.0.6 的覆盖升级会按**上一版清单**清掉本版
已移除的文件。但如果某个目录里还躺着**更早版本**写下的文件（那些版本的清单早被覆盖掉了），
任何清单都不认识它们 —— 安装器与卸载器会（按设计，且这正是「不误删无关文件」的安全属性）
把它们当作「非本产品文件」保留。典型症状：装完以后「用内置模板新建」里多出早已移除的角色。

给这种情况准备了一个**只认产品命名空间、默认 dry-run** 的清理工具：

```powershell
# 先看清单（什么都不删）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\clean-legacy-install.ps1 -InstallDir "<安装目录>"
# 确认没问题再执行
powershell -NoProfile -ExecutionPolicy Bypass -File tools\clean-legacy-install.ps1 -InstallDir "<安装目录>" -Apply
```

它要求目标目录同时具备 `.azurlandeskpet-install` 标记与 `product=AzurLaneDeskPet` 的 `files.json`
（否则直接拒绝执行），并且只处理 `assets\builtin\characters\<id>\`（含 `info.json` 才算产品模板）、
`assets\builtin\lines\<id>.txt`、`assets\builtin\voices\<id>\` 这三处，判定标准是「不在当前负载清单里」；
其它文件一律不碰，目录只在已空时才删。
